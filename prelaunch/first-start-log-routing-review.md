# First-start database log routing review

Status: source-only independent review; **no judge change justified by this proposed failure**. Clean run [33911646203](https://github.com/tylerhanny/wow-server-forge/actions/runs/33911646203) remains in progress. This review does not claim startup succeeded or that the eventual logs are clean.

The proposed defect was that ordinary creation of missing disposable schemas must make `Errors.log` nonempty and fail the gate. Exact pinned source disproves that specific inference:

1. [LogCommon.h](https://github.com/mod-playerbots/azerothcore-wotlk/blob/47960183bb03b83e8943eb2f0f39c16df9710c9d/src/common/Logging/LogCommon.h#L24) defines `ERROR=2`, `WARN=3`, and `INFO=4`.
2. [Appender::write](https://github.com/mod-playerbots/azerothcore-wotlk/blob/47960183bb03b83e8943eb2f0f39c16df9710c9d/src/common/Logging/Appender.cpp#L53) returns when `appender level < message level`. The pinned [world config](https://github.com/mod-playerbots/azerothcore-wotlk/blob/47960183bb03b83e8943eb2f0f39c16df9710c9d/src/server/apps/worldserver/worldserver.conf.dist#L677) sets `Appender.Errors=2,2,0,Errors.log,w`; it rejects WARN messages even when a logger lists that appender.
3. [DBUpdater::Create](https://github.com/mod-playerbots/azerothcore-wotlk/blob/47960183bb03b83e8943eb2f0f39c16df9710c9d/src/server/database/Updater/DBUpdater.cpp#L248) emits the missing-schema message at WARN through `sql.updates`. `Logger.sql.updates=4,Console Server Errors` accepts it, but the Errors appender rejects its severity. Console and Server still preserve it.
4. [MySQLConnection::Open](https://github.com/mod-playerbots/azerothcore-wotlk/blob/47960183bb03b83e8943eb2f0f39c16df9710c9d/src/server/database/Database/MySQLConnection.cpp#L160) emits the initial connection failure at ERROR through `sql.driver`. There is no active explicit `Logger.sql.driver`; [nearest-parent logger resolution](https://github.com/mod-playerbots/azerothcore-wotlk/blob/47960183bb03b83e8943eb2f0f39c16df9710c9d/src/common/Logging/Log.cpp#L258) selects `Logger.sql=4,Console Server`, which has no Errors appender.

[DatabaseLoader](https://github.com/mod-playerbots/azerothcore-wotlk/blob/47960183bb03b83e8943eb2f0f39c16df9710c9d/src/server/database/Database/DatabaseLoader.cpp#L105) handles `ER_BAD_DB_ERROR` by creating the database and reopening it when updates and automatic setup are enabled. Successful recovery clears the error; the later pool-open error message occurs only if recovery failed. Dry-run skips the interactive creation question. The pinned creation SQL uses `UTF8MB4` / `utf8mb4_general_ci`; [Populate](https://github.com/mod-playerbots/azerothcore-wotlk/blob/47960183bb03b83e8943eb2f0f39c16df9710c9d/src/server/database/Updater/DBUpdater.cpp#L434) separately detects an empty schema with `SHOW TABLES` and applies base SQL.

The world process [initializes logging before StartDB](https://github.com/mod-playerbots/azerothcore-wotlk/blob/47960183bb03b83e8943eb2f0f39c16df9710c9d/src/server/apps/worldserver/Main.cpp#L191). [AppenderFile](https://github.com/mod-playerbots/azerothcore-wotlk/blob/47960183bb03b83e8943eb2f0f39c16df9710c9d/src/common/Logging/AppenderFile.cpp#L70) opens a static filename immediately with its configured `w` mode, so Errors.log is truncated at logger initialization, before database setup. Initial [World::LoadConfigSettings](https://github.com/mod-playerbots/azerothcore-wotlk/blob/47960183bb03b83e8943eb2f0f39c16df9710c9d/src/server/game/World/World.cpp#L168) does not reload logging unless `reload` is true. The gate also captures each process's console output separately.

Disposition: retain the existing run, fixture, strict error-file check, and untouched logs. Expected handled first-start connection errors/warnings may appear in console/Server output; actual logs must establish successful schema creation, population, updates, and completed startup before those particular messages are classified as recovered setup. This is not a blanket exception for connection errors, SQL errors, or nonempty Errors.log. No source, flags, timeout, logging threshold, migration behavior, or judge was changed.
